# Real Props

A multi-role real-estate marketplace built with **Laravel 11**, **Livewire 3**, **Tailwind CSS**, **Spatie Permissions/Medialibrary/ActivityLog**, **Laravel Scout** and **Laravel Cashier (Stripe)**.

Guests browse, search, compare (up to 4) and enquire about listings. Agents manage their own listings, inquiries, tour requests, analytics and subscription. Admins moderate listings, verify agents, manage users, master data, blog, CMS pages, plans, settings and reports.

## Requirements

| Tool | Version |
| --- | --- |
| PHP | ^8.2 (8.2+ supported; developed and CI-tested on 8.2) |
| Laravel | 11.x |
| Composer | 2.x |
| Node.js | 20+ (22 LTS recommended) |
| Database | MySQL 8+, MariaDB 10.6+ or SQLite |

Optional: Redis (cache/sessions/queues), Stripe keys (subscriptions), a Scout driver other than `collection`.

## Quick start

```bash
git clone <repo-url> real-props && cd real-props

composer install
npm install && npm run build          # or: npm run dev

cp .env.example .env
php artisan key:generate

# point DB_CONNECTION/DB_* at MySQL (or keep sqlite), then:
php artisan migrate --seed

php artisan serve                     # http://127.0.0.1:8000
```

Seeded demo accounts:

| Role | Email | Password |
| --- | --- | --- |
| Admin | `admin@realprops.test` | `password` |
| Agent / Member | generated by factories (see `database/seeders/UserSeeder.php`) | `password` |

## Docker

```bash
cp .env.docker .env.docker.local   # optional overrides
docker compose up -d --build
```

Services: `nginx` (public, `HTTP_PORT` default `8080`), `app` (PHP-FPM 8.2), `db` (MySQL 8.4), `redis`, `queue` (worker) and `scheduler`.

The app image is multi-stage: Vite assets are built in a Node stage, Composer dependencies in a Composer stage, and the final image is `php:8.2-fpm-alpine`. The entrypoint can run migrations/optimizations via `RUN_MIGRATIONS`, `RUN_SEEDERS`, `OPTIMIZE` and `GENERATE_APP_KEY` env flags.

## Roles & permissions

Roles live in `App\Enums\UserRole` and are synced by `Database\Seeders\RoleSeeder` through Spatie Permission.

| Permission | User | Agent | Admin |
| --- | :---: | :---: | :---: |
| `properties.view` | ✅ | ✅ | ✅ |
| `properties.create` / `update` / `delete` | | ✅ | ✅ |
| `properties.approve` / `feature` | | | ✅ |
| `users.manage` | | | ✅ |
| `agents.verify` | | | ✅ |
| `reports.view` | | | ✅ |
| `settings.manage` | | | ✅ |

Agents are only shown publicly once an admin sets `agent_profiles.verified_at`.

## Feature map

**Public site** — home with hero search + featured listings, property search with filters/sort/pagination (Livewire, URL-persisted), property detail with gallery, amenities, map, related listings, inquiry + tour-request forms, agent directory/profiles, blog (categories, tags), CMS pages, contact form (throttled), compare up to 4 listings (session-driven), dark mode.

**Members** — dashboard, favorites, saved searches (with match notifications), compare list, inquiry history, profile management.

**Agents** — dashboard + analytics (Chart.js), listing CRUD with media upload, moderation status, inquiry inbox with reply, tour-request schedule, subscription plans (Stripe Checkout + Customer Portal), profile.

**Admin** — analytics dashboard, listing moderation (approve/reject/feature), user management (suspend/unsuspend), agent verification, master data (amenities, types, states, cities, categories, tags), blog posts, CMS pages, subscription plans, settings (general/SEO/listings/social), contact-message inbox, reports, activity log.

**Platform** — Sanctum REST API (v1), Scout search, Spatie Media Library, Spatie Activity Log, Cashier subscriptions, notifications (mail + in-app), rate limiting on sensitive endpoints, security headers/CSP middleware, custom error pages (403/404/419/429/500).

## HTTP API (v1)

Base path: `/api/v1`. JSON in/out. Bearer token via Sanctum.

Public: `POST /register`, `POST /login`, `GET /properties`, `GET /properties/featured`, `GET /properties/search`, `GET /properties/{id}`, `GET /agents`, `GET /agents/{id}`, `GET /posts`, `GET /posts/{slug}`, `GET /categories`, `GET /tags`, `GET /plans`.

Authenticated (`Authorization: Bearer <token>`): `POST /logout`, `GET|PATCH /me`, `GET|POST|DELETE /favorites[/{property}]`, `GET|POST /inquiries`, `POST /tours/{propertyId}`.

Webhook: `POST /api/v1/webhooks/stripe` (Cashier).

A ready-to-import Postman collection is in [`docs/postman/RealProps.postman_collection.json`](docs/postman/RealProps.postman_collection.json).

## Testing, linting & static analysis

```bash
php artisan test                 # Pest 3 (SQLite :memory:, RefreshDatabase + RoleSeeder)
vendor/bin/pint                  # Laravel code style
vendor/bin/pint --test           # style check (used in CI)
vendor/bin/phpstan analyse       # Larastan level 5 (see phpstan-baseline.neon)
```

`tests/Feature/SmokeTest.php` renders every GET route for guest/member/agent/admin so missing or broken Blade views fail CI immediately.

CI (`.github/workflows/ci.yml`) runs the test suite, Pint, PHPStan and a Docker image build on every push/PR.

## Database

Mermaid ERD: [`docs/ERD.md`](docs/ERD.md).

Core tables: `users`, `agent_profiles`, `properties`, `property_images`, `amenity_property`, `inquiries`, `tour_requests`, `favorites`, `saved_searches`, `posts`, `categories`, `tags`, `post_tag`, `pages`, `plans`, `subscriptions`, `contact_messages`, `settings`, `activities`, `notifications`, plus master data (`amenities`, `property_types`, `states`, `cities`). Compare lists are session-driven and not persisted.

```bash
php artisan migrate:fresh --seed   # rebuild + seed demo data
```

## Environment variables

`.env.example` documents every key. Notables:

| Key | Notes |
| --- | --- |
| `DB_*` | `mysql`/`mariadb`/`sqlite` |
| `SCOUT_DRIVER` | `collection` (default), `database`, `algolia`, `meilisearch`… |
| `STRIPE_KEY`, `STRIPE_SECRET`, `STRIPE_WEBHOOK_SECRET` | Agent subscriptions (Cashier) |
| `FILESYSTEM_DISK` | `public` for media URLs |
| `APP_REQUIRE_EMAIL_VERIFICATION_FOR_AGENTS` | gate agent registration (default `true`) |

Runtime site settings (site name, SEO, listing rules, social links) are **not** env-driven — admins manage them in the `/admin/settings` UI (stored in the `settings` table).
